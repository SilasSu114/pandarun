# 第二关推箱子贴身推法修复提示词

你是一个 Godot 4.7 游戏开发 Agent。请在 `projects/godot-gravity-tutorial-demo/` 项目中修复第二关推箱子的手感问题。

当前问题是：玩家推箱子时，箱子不是被人物贴身推过去，而是像自己滑过去或闪现过去。请把推箱逻辑改成必须由玩家实际接触并推动，箱子不能在没有接触时自己移动。

## 修改范围

只修改 `projects/godot-gravity-tutorial-demo/`。

重点检查：

```text
scripts/player.gd
scripts/push_box.gd
scenes/level_2.tscn
```

不要修改 `projects/godot-gravity-tutorial-demo-(4.3)/`。不要重做整个关卡，也不要引入菜单、存档、音效或新美术资源。

## 当前问题定位

当前 `PushBox` 是一个 `CharacterBody2D`，通过 `push_from_player()` 设置一个独立的 `_push_velocity`，然后在自己的 `_physics_process()` 里移动。这个实现会让箱子的运动和玩家实际接触状态脱节，容易表现成滑过去、抢跑或闪现。

请不要再依赖这种“玩家只发一个方向，箱子自己往前跑”的逻辑。

## 目标行为

推箱子必须满足下面这些条件：

1. 只有玩家和箱子实际发生接触时，箱子才允许移动。
2. 玩家停止按方向键时，箱子必须立刻停止。
3. 玩家离开箱子接触范围时，箱子必须立刻停止。
4. 箱子的移动速度不能明显快于玩家的推动速度。
5. 玩家不能穿过箱子，也不能绕过箱子直接把它挤到开关上。
6. 箱子碰到墙、障碍物或开关阻挡物时应立即停住，不能滑过去。
7. 玩家反向推箱子时，必须重新接触箱子的另一侧，箱子才会反向移动。
8. 箱子到达开关位置时，应该是被连续推动到位，而不是突然吸附或瞬移过去。

## 推荐实现方向

请优先保留 `CharacterBody2D` 箱子，但把移动方式改成由玩家的实际接触驱动：

1. 玩家在 `move_and_slide()` 后检查碰撞结果，只在确实接触到箱子时才向箱子传递推动信息。
2. 推动信息必须包含：
   - 推动方向；
   - 玩家当前实际水平推动速度或至少一个与玩家移动速度一致的推动强度；
   - 本次物理帧内的接触状态。
3. 箱子不要保存跨帧的推动速度。每帧没有新的接触输入就移动量为零。
4. 箱子移动时使用碰撞感知的移动方式，例如 `move_and_collide()` 或等效逻辑。
5. 不要使用 `position += ...`、`global_position = ...`、`Tween` 或任何直接赋值坐标的方式移动箱子。
6. 如果玩家与箱子之间有极小的间隙，可以允许一个很小的接触容差，例如 `4` 到 `8` 像素，但不能用它让箱子大段滑行。
7. 箱子与玩家应该保持贴身推进，不能出现玩家已经停下但箱子还在继续移动的情况。

可以按下面的逻辑组织：

```gdscript
# 玩家侧
func _try_push_boxes(move_axis: float) -> void:
    if is_zero_approx(move_axis):
        return

    var push_direction := screen_right * signf(move_axis)
    var push_speed := absf(_lateral_velocity)

    for collision_index in get_slide_collision_count():
        var collision := get_slide_collision(collision_index)
        var collider := collision.get_collider()

        if not collider or not collider.is_in_group("push_box"):
            continue

        if collision.get_normal().dot(push_direction) >= -0.5:
            continue

        collider.push_from_player(push_direction, push_speed)
```

```gdscript
# 箱子侧
var _current_push_direction := Vector2.ZERO
var _current_push_speed := 0.0

func push_from_player(new_push_direction: Vector2, new_push_speed: float) -> void:
    _current_push_direction = new_push_direction.normalized()
    _current_push_speed = maxf(0.0, new_push_speed)

func _physics_process(delta: float) -> void:
    var motion := _current_push_direction * _current_push_speed * delta
    _current_push_direction = Vector2.ZERO
    _current_push_speed = 0.0

    if not motion.is_zero_approx():
        move_and_collide(motion)
```

这只是一个参考结构，不必逐字照抄。关键是：箱子每帧的移动量必须来自玩家本帧的接触推动，而不是自己保存速度继续滑行。

## 需要移除或避免的逻辑

请检查并移除下面这些容易造成“闪现”的实现：

- 箱子内部保存 `_push_velocity` 并在下一帧继续使用。
- 箱子移动速度高于玩家移动速度。
- 玩家只传入方向，不传入接触和速度。
- 使用 `Tween` 或协程把箱子移动到某个目标点。
- 使用大范围检测区域代替真实接触。
- 使用 `global_position` 直接移动箱子。
- 用大碰撞体让箱子提前触发开关。

## 碰撞与层级

请确认第二关的碰撞关系正确：

1. 玩家必须能和箱子发生碰撞。
2. 玩家必须被箱子阻挡，不能穿过箱子。
3. 箱子必须能被墙、障碍物和边界阻挡。
4. 箱子不能被开关当作可以自由穿过的对象。
5. 开关触发应由箱子接触产生，而不是因为碰撞体过大提前触发。

如果需要调整碰撞层或遮罩，请保持现有玩法流程不变。

## 重力旋转兼容

推箱逻辑必须继续兼容重力旋转：

1. 旋转结束后，玩家和箱子的重力方向都要更新。
2. 玩家推动箱子的方向必须基于当前屏幕方向。
3. 箱子在新的重力方向下仍要能被贴身推动。
4. 不能因为重力旋转导致箱子突然跳位或穿过墙。

## 验收标准

请手动测试以下场景：

1. 玩家站在箱子一侧推动，箱子应该被连续推过去，不能闪现。
2. 玩家松开方向键，箱子立刻停止。
3. 玩家离开箱子，箱子不再移动。
4. 玩家反向推箱子，必须先接触另一侧才能反向移动。
5. 箱子撞墙后停止，不能穿墙。
6. 箱子接触开关后，开关激活，但箱子不是突然吸附到开关上的。
7. 在四个重力方向下，玩家都能正常贴身推箱子。
8. 玩家不能穿过箱子，也不能绕过箱子直接把出口流程触发掉。
