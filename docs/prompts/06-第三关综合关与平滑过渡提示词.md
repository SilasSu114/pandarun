你是一个 Godot 4.7 游戏开发 Agent。请在 `projects/godot-gravity-tutorial-demo/` 项目中实现第三关综合关，并让第一关、第二关结束后都能丝滑过渡到下一关。

不要修改 `projects/godot-gravity-tutorial-demo-(4.3)/`。不要加入菜单、存档、音效或新美术资源。继续遵守 `docs/notes/01-占位素材替换约定.md`。

- 只修改 `projects/godot-gravity-tutorial-demo/`。
- 保持现有重力旋转、四面封闭边界、1080 x 1080 房间结构和占位视觉。

## 统一关卡过渡

请优先把“第一关 -> 第二关”和“第二关 -> 第三关”的过渡逻辑统一，不要在每个关卡脚本里各写一份重复的淡入淡出代码。

推荐做法是新增一个简单的 `LevelRouter` 自动加载节点：

```text
scripts/level_router.gd
```

它负责：

1. 提供一个全屏 `CanvasLayer` 过渡层。
2. 提供 `goto_scene(path: String)` 方法。
3. 过渡开始时淡出为黑。
4. 场景切换后淡入为新关卡。
5. 过渡期间禁止重复触发。

参考流程：

```gdscript
func goto_scene(path: String) -> void:
    if _changing:
        return

    _changing = true
    var out_tween := create_tween()
    out_tween.tween_property(_overlay, "color:a", 1.0, 0.6)
    await out_tween.finished

    get_tree().change_scene_to_file(path)
    await get_tree().process_frame

    var in_tween := create_tween()
    in_tween.tween_property(_overlay, "color:a", 0.0, 0.35)
```

然后：

- 第一关出口触发后调用 `LevelRouter.goto_scene("res://scenes/level_2.tscn")`。
- 第二关出口触发后调用 `LevelRouter.goto_scene("res://scenes/level_3.tscn")`。
- 如果第一关已经有自己的过渡层，可以替换成 `LevelRouter`，避免双重黑场。
- 过渡层必须放在高层级 `CanvasLayer` 上，不能被重力旋转影响。

## 第三关核心结构

请新增第三关场景：

```text
scenes/level_3.tscn
scripts/level_3.gd
```

第三关仍然是一个 `1080 x 1080` 正方形房间：

- 四边有完整静态墙。
- `Camera2D` 位置为 `(540, 540)`。
- 保留独立 `GravityManager` 实例。
- `Space` 顺时针旋转重力，动画仍然平滑。
- 玩家、箱子都会受当前重力影响。

第三关综合使用三种机制：

1. 玩家开关。
2. 可推动箱子开关。
3. 门和出口解锁。

## 玩法流程

第三关的解谜顺序如下：

1. 玩家进入关卡后先到达并触发“开关 1”。
2. “开关 1”解锁“门 1”。
3. 玩家通过重力旋转，把“箱子 1”推到“开关 2”。
4. “箱子 1”接触“开关 2”后，“门 2”解锁。
5. 玩家跳或移动到“开关 3”并触发它。
6. “开关 3”解锁“门 3”。
7. 玩家继续旋转重力，把“箱子 2”推到“开关 4”。
8. “箱子 2”接触“开关 4”后，出口激活。
9. 玩家最后一次旋转重力，到达激活出口，第三关过关。

不需要完全复刻参考图的坐标，但上面这条逻辑链必须成立，并且不能被其他路径绕过。

## 开关设计

开关使用 `Area2D`，建议统一为一个可复用的 `SwitchPlate` 或新场景：

```text
scenes/switch_plate.tscn
scripts/switch_plate.gd
```

如果继续使用现有 `SwitchPlate` 脚本，请扩展为支持两种激活方式：

```gdscript
enum Activator {
    PLAYER,
    PUSH_BOX,
}
```

- 开关 1：玩家触发。
- 开关 2：箱子 1 触发。
- 开关 3：玩家触发。
- 开关 4：箱子 2 触发。

要求：

1. 开关激活后保持激活状态。
2. 玩家不能触发箱子开关。
3. 箱子不能触发玩家开关。
4. 开关只能触发一次，不要重复解锁。
5. 开关触发必须来自真实接触，不能靠很大的检测区提前触发。
6. 激活和未激活状态用颜色或形状区分，不要用文字。

如果 `player.tscn` 目前没有分组，请把玩家加入 `player` 分组，方便开关判断。

## 门设计

门使用 `StaticBody2D` 阻挡玩家和箱子，建议统一为：

```text
scenes/gate.tscn
scripts/gate.gd
```

门需要包含：

1. `StaticBody2D` 碰撞体。
2. 占位视觉节点。
3. `open()` 方法。
4. 打开后禁用碰撞并做一个简单的视觉变化。

参考逻辑：

```gdscript
func open() -> void:
    if is_open:
        return

    is_open = true
    collision_shape.set_deferred("disabled", true)
    visual.modulate = Color(1, 1, 1, 0.25)
```

门状态要求：

1. 门 1 由开关 1 解锁。
2. 门 2 由开关 2 解锁。
3. 门 3 由开关 3 解锁。
4. 门打开后保持打开。
5. 门打开前必须真实阻挡玩家和箱子。
6. 不能让玩家通过跳跃、旋转或绕路直接跳过某个门。

不要用 `Area2D` 做门，因为门需要真实阻挡。

## 箱子设计

箱子继续复用第二关的推箱机制。

第三关需要两个箱子：

```text
Box1
Box2
```

要求：

1. 两个箱子都加入 `push_box` 分组。
2. 箱子必须受当前重力影响。
3. 玩家可以贴身推动箱子。
4. 箱子不能闪现、吸附或穿墙。
5. 箱子接触对应开关后激活开关。
6. 一个箱子只能激活分配给它的开关，不要两个箱子互相通用。

如果当前箱子实现已经修好丝滑手感，请不要为了第三关重新写一套完全不同的箱子逻辑。

## 关卡布局

布局可以参考综合关示意图，但不需要逐像素复刻。

必须满足：

1. 玩家出生点不会被门或箱子卡住。
2. 开关 1 在第一段可达区域内。
3. 门 1 打开前，玩家不能到达后续解谜区。
4. 箱子 1 放在可以通过重力旋转推动到开关 2 的位置。
5. 门 2 打开前，玩家不能到达开关 3。
6. 玩家跳到开关 3 的路径必须可达，但不应该一眼就能直接走到。
7. 箱子 2 放在可以通过重力旋转推动到开关 4 的位置。
8. 出口在所有前置开关完成后才可达。
9. 四边封闭，玩家和箱子在任何重力方向都不会掉出地图。
10. 房间内不要塞得太满，保留清晰的移动和推箱空间。

## 视觉占位

继续使用简单占位视觉：

- 玩家：现有占位方块。
- 箱子：明显矩形色块。
- 开关：黄色或亮色小方块，激活后变色。
- 门：红色或明显阻挡色块，打开后变暗或半透明。
- 出口：绿色矩形，未激活时暗色或半透明。
- 过渡层：全屏黑色 `ColorRect`。

所有可交互对象继续保持 `Visual` 与碰撞节点分离，方便后续替换真实素材。

## 验收标准

完成后请手动验证：

1. 第一关出口触发后，能丝滑进入第二关。
2. 第二关出口触发后，能丝滑进入第三关。
3. 第三关开始时，玩家和箱子都处于初始重力方向。
4. `Space` 每按一次就顺时针旋转重力，并且有平滑过渡动画。
5. 玩家触发开关 1 后，门 1 打开。
6. 箱子 1 被推到开关 2 后，门 2 打开。
7. 玩家触发开关 3 后，门 3 打开。
8. 箱子 2 被推到开关 4 后，出口激活。
9. 玩家接触激活出口后，第三关过关。
10. 玩家不能跳过任何一扇关闭的门。
11. 玩家不能触发箱子开关，箱子不能触发玩家开关。
12. 第三关没有文字引导。
13. 四边封闭，任何重力方向下玩家和箱子都不会掉出地图。
