# 第二关推箱子到达开关路径修复提示词

你是一个 Godot 4.7 游戏开发 Agent。请在 `projects/godot-gravity-tutorial-demo/` 项目中修复第二关的一个布局问题：目前箱子要推到开关位置，但接近路径好像被障碍物挡住，导致箱子无法正常到达开关。

请优先修复路径，不要通过瞬移、吸附、扩大检测区域或直接改脚本逻辑来“绕过”这个布局问题。

## 修改范围

只修改 `projects/godot-gravity-tutorial-demo/`。

重点检查：

```text
scenes/level_2.tscn
scripts/switch_plate.gd
scripts/push_box.gd
```

不要修改 `projects/godot-gravity-tutorial-demo-(4.3)/`。不要重做整个关卡，也不要加入菜单、存档、音效或新美术资源。

## 当前疑点

当前场景里有一个 `SwitchStopper`，它是 `StaticBody2D`，位置在 `(154, 708)` 左右，碰撞盒宽度大约是 `100`。它很可能正好卡在箱子接近 `SwitchPlate` 的路径上，导致箱子还没接触到开关就被挡住了。

除非有明确的设计理由，否则不要让它继续挡在开关接触路径的前面。

## 目标行为

箱子必须能够被玩家连续推动到开关接触区，然后激活开关。整个接近过程应该像正常的推箱子，而不是闪现或吸附。

请满足以下要求：

1. 玩家推动箱子的路径上不能有意外障碍物。
2. 箱子能接触到 `SwitchPlate` 的碰撞区。
3. `SwitchPlate` 能被箱子触发。
4. 箱子碰到墙、货架或其他合法障碍物时仍应正常停住。
5. 不要让箱子穿过墙或玩家。
6. 不要用瞬移、吸附或直接改坐标的方式让箱子到达开关。

## 修复方向

请按下面的顺序检查和修复：

1. 列出第二关里所有可能阻挡箱子路径的静态物体，特别是：
   - `SwitchStopper`
   - `BoxShelf`
   - `CeilingShelf`
   - 四面墙
2. 判断哪些障碍物是有意设计，哪些是误挡路径。
3. 如果 `SwitchStopper` 的作用只是装饰或阻挡箱子继续滑动，请做下面其中一种处理：
   - 直接删除；
   - 移动到不会挡住箱子接近开关的位置；
   - 保留视觉，但移除碰撞，或改成不参与箱子推路径碰撞的节点。
4. 如果需要保留一个真正的阻挡块，它应该放在开关接触区之后或另一侧，不能放在箱子接近开关的必经之路上。
5. 如果调整 `SwitchStopper` 后仍然接触不到开关，再检查 `SwitchPlate` 的位置和碰撞区大小。
6. 如果开关碰撞区过小，可以适当扩大，但不要扩大到能让玩家或箱子在明显没接触时提前触发。

## 碰撞与层级

请确认：

1. `SwitchPlate` 只对箱子生效，不对玩家生效。
2. 玩家仍然被箱子阻挡，不能穿过箱子。
3. 箱子仍然被墙和合法障碍物阻挡。
4. 被移除或禁用碰撞的 `SwitchStopper` 不应该继续阻止箱子到达开关。

## 验收标准

修复后请手动验证：

1. 从第二关初始状态开始，按设计流程触发重力旋转。
2. 玩家能沿当前屏幕方向推箱子。
3. 箱子沿推路径移动时，不会被 `SwitchStopper` 提前挡住。
4. 箱子能真实接触开关并激活出口。
5. 箱子到达开关后没有瞬移、吸附或穿墙。
6. 玩家仍然不能穿过箱子，也不能直接用身体触发开关。
7. 房间四边封闭，箱子和玩家在任何重力方向下都不会掉出地图。
8. 第二关仍然没有任何文字引导。
