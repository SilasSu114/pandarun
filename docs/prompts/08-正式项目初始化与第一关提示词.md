# 正式项目初始化与第一关提示词

你是一个 Godot 4.7 游戏开发 Agent。Demo 已经完成验证。现在请不要再修改现有 Demo 项目，而是在本工作区里新建一个正式项目子文件夹，并实现正式项目的基础操作教学关。

## 新建位置

请在 `projects/` 下新建一个独立子文件夹：

```text
projects/godot-gravity-main/
```

不要修改或覆盖：

```text
projects/godot-gravity-tutorial-demo/
projects/godot-gravity-tutorial-demo-(4.3)/
```

如果需要复用 Demo 里的核心代码，请只复制真正可复用的脚本或场景，例如玩家、重力管理、推箱、门、开关等。不要复制 `.godot/` 缓存、日志文件、旧关卡场景或无用文件。

## 项目初始化

新项目应该是一个干净的 Godot 4.7 项目：

```text
projects/godot-gravity-main/
  project.godot
  README.md
  scenes/
    player.tscn
    level_1.tscn
  scripts/
    player.gd
    gravity_manager.gd
    level_1.gd
```

请把主场景设置为 `scenes/level_1.tscn`。

第一关房间使用 `1080 x 1080` 正方形。四面都要有静态墙，任何重力方向下玩家都不能掉出地图。

## 第一关定位

第一关是基础操作教学关。

目标是让玩家掌握基础操作，并自己领悟到“场景旋转”可以解决原本过不去的障碍。

这一关不做复杂解谜，不加入箱子和开关。只需要：

1. 玩家移动。
2. 玩家跳跃。
3. 场景顺时针旋转 90 度。
4. 通关条件物和出口。

## 场景布局

请参考下面的布局意图，不需要逐像素复刻：

```text
+--------------------------------------+
|                 [出口]                |
|                                      |
|                                      |
|                                      |
|                     [通关条件物]      |
|                                      |
|                                      |
|            [矮障碍一]                |
|                                      |
|                    [矮障碍二]         |
|                                      |
|                          [高障碍]     |
|[玩家]                                 |
+--------------------------------------+
```

具体要求：

1. 玩家出生点在左下角。
2. 房间中下有一个矮障碍一，玩家可以跳过去。
3. 房间右下有一个矮障碍二，玩家可以跳上去。
4. 矮障碍二旁边或上方有一个高障碍，玩家无法通过普通跳跃直接上到通关条件物。
5. 通关条件物放在右上区域附近。
6. 出口放在中上区域附近。
7. 出口在通关条件物被获取前不能触发过关。

## 玩法流程

第一关的流程如下：

1. 玩家学会左右移动。
2. 玩家跳过矮障碍一。
3. 玩家跳上矮障碍二。
4. 玩家尝试跳上高障碍，但发现无法直接上去。
5. 玩家尝试使用 `Space` 旋转场景。
6. 玩家通过旋转后的新方向移动到通关条件物。
7. 玩家获取通关条件物后，出口激活。
8. 玩家再次旋转场景，回到可达出口的位置。
9. 玩家接触激活出口，第一关过关。

## 操作

继续使用这些输入：

- `A` / `D`：当前屏幕左右移动。
- `W`：沿当前重力反方向跳跃。
- `Space`：顺时针旋转场景 90 度。

场景旋转仍然要有平滑过渡动画，不能瞬间跳变。

旋转后，玩家、相机和 UI 都要按同一重力方向更新。

## 机制要求

请实现或复用以下机制：

1. `CharacterBody2D` 玩家。
2. `GravityManager` 统一管理当前重力索引、重力向量、相机旋转和 UI 旋转。
3. 玩家移动方向必须基于当前屏幕方向。
4. 玩家跳跃方向必须是当前重力反方向。
5. `Space` 每次只触发一次旋转，不能按住连发。
6. 旋转动画期间禁止连续触发下一次旋转。
7. 旋转完成后，玩家实际重力再切换到新方向。

## 通关条件物

通关条件物可以使用一个 `Area2D` 表示。

要求：

1. 玩家接触后触发拾取。
2. 拾取后出口激活。
3. 拾取前出口保持未激活状态。
4. 拾取后通关条件物消失或变为已获取状态。

不要用文字解释它是钥匙、开关还是其他东西。视觉上可以先用一个亮色小方块或简单图标占位。

## 出口

出口也使用一个 `Area2D`。

要求：

1. 未激活时用暗色或半透明视觉。
2. 激活后用亮色视觉。
3. 未激活时玩家接触无效。
4. 激活后玩家接触触发过关。

## 视觉占位

继续使用简单占位视觉：

- 玩家：现有占位方块或简单形状。
- 墙体：深色矩形。
- 矮障碍：中等色块。
- 高障碍：更高、更明显的色块。
- 通关条件物：亮色小方块。
- 出口：绿色矩形，未激活时暗色或半透明。

所有可交互对象继续保持 `Visual` 与碰撞节点分离，方便后续替换真实素材。

## 不显示文字引导

这一关不要显示任何文字提示。

不要出现：

1. “按 A / D 移动”。
2. “按 W 跳跃”。
3. “按 Space 旋转场景”。
4. “拾取钥匙”。
5. “前往出口”。
6. “第 1 关”。

关卡引导应该通过障碍高度、空间布局和视觉状态让玩家自己理解。

## 验收标准

完成后请手动验证：

1. 玩家出生在左下角，不会掉出地图。
2. `A` / `D` 能正常移动。
3. `W` 能正常跳跃。
4. 玩家不能直接跳上高障碍。
5. 玩家不能在未拾取通关条件物时直接通关。
6. `Space` 触发顺时针旋转，并且有平滑过渡动画。
7. 连续按四次 `Space` 后，场景和重力回到初始状态。
8. 玩家能通过旋转场景拿到通关条件物。
9. 拾取通关条件物后出口激活。
10. 玩家接触激活出口后第一关过关。
11. 场景中没有文字引导。
12. 四边封闭，玩家在任何重力方向都不会掉出地图。
