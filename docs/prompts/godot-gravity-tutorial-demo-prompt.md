# Godot 重力旋转教学关：最低可运行 Demo 开发提示词

你是一名 Godot 4 游戏开发 Agent。请为 21 天 GameJam 项目开发一个最低可运行的教学关 Demo。不要做菜单、存档、音效、复杂美术或通用关卡编辑器，目标是让一个玩家角色在一个方形房间中完成移动、跳跃、重力旋转、钥匙激活出口、出口过关的完整流程。

## 项目目标

用 Godot 4 实现 2D 横版教学关。核心机制是：每次按下 `Space`，场景重力顺时针旋转 90 度，玩家会向新的重力方向下落，同时画面/界面也同步旋转 90 度。房间四边都必须有静态碰撞墙，玩家在任何重力方向下都不会掉出地图外。

## 建议工程结构

```text
projects/godot-gravity-tutorial-demo/
  project.godot
  scenes/
    main.tscn
    player.tscn
  scripts/
    main.gd
    player.gd
    gravity_manager.gd
```

如果 Agent 判断单场景实现更简洁，也允许把少量节点放在 `main.tscn` 中，但必须保证场景结构清晰、脚本职责明确。

## 玩家控制

- 使用 `CharacterBody2D` 实现玩家。
- 初始重力方向为屏幕向下，玩家从房间左下角开始。
- `A` / `D`：沿当前屏幕的左右方向移动。
- `W`：沿当前重力反方向跳跃。
- 跳跃高度必须明显低于高处障碍、钥匙和出口，不允许玩家直接跳到过关点或钥匙上。
- 玩家应能稳定站在地面墙上，并且在重力旋转后自然落到新的“地面”。

## 重力旋转机制

1. 使用一个 `GravityManager` 或集中脚本管理当前重力状态。
2. 初始重力向量为 `Vector2.DOWN`。
3. 每次点击 `Space`，重力按顺时针方向切换 90 度：
   - 向下 -> 向左
   - 向左 -> 向上
   - 向上 -> 向右
   - 向右 -> 向下
4. 只响应 `Input.is_action_just_pressed("space_rotate")`，按住 `Space` 不能连续旋转。
5. `Space` 触发后：
   - 更新玩家使用的重力向量。
   - 将主 `Camera2D.rotation_degrees += 90`。
   - 将 UI 根节点同步旋转 90 度，保证提示文字和界面随重力旋转。
6. 玩家移动和跳跃必须基于当前重力方向计算：
   - 当前屏幕“右”方向可以由当前重力向量的垂直方向推导。
   - 当前跳跃方向必须是当前重力向量的反方向。
7. 房间的上、下、左、右四边必须有 `StaticBody2D` 墙体，覆盖完整边界，避免玩家在任意重力方向掉出地图。

## 教学关流程

关卡流程参考下面顺序实现：

1. 玩家进入关卡后，屏幕上出现提示：“按 A / D 左右移动”。
2. 玩家完成左右移动后，提示其向右移动。
3. 玩家碰到右侧墙壁或障碍后：
   - 显示提示：“按 W 跳跃”。
   - 同时解锁 `Space` 重力旋转能力。
   - 在此之前按 `Space` 不能触发旋转。
4. 玩家尝试跳上更高障碍物时，或进入高处障碍附近的提示区域后，显示提示：“按 Space 顺时针旋转重力”。
5. 玩家靠近钥匙后拾取钥匙。
6. 钥匙拾取后出口激活，出口从不可用状态变为可用状态。
7. 玩家接触已激活出口后过关，显示“通关”或“Level Clear”。

## 关卡布局

请搭建一个简洁的方形房间，类似下面示意：

```text
+--------------------------------------+
|                [出口]                 |
|                                      |
|                                      |
|                       [钥匙]          |
|                                      |
|          [低矮障碍]      [高障碍]       |
|                                      |
|[玩家]                                 |
+--------------------------------------+
```

实现时可以调整比例，但必须满足：

- 四边封闭。
- 有一个低矮障碍用于教 W 跳跃。
- 有一个更高障碍物或高台，正常跳跃无法直接越过。
- 钥匙放在正常跳跃拿不到的位置，必须通过重力旋转改变行进方向后才能到达。
- 出口初始不可用或不可交互，拾取钥匙后激活。
- 出口不能在钥匙拾取前就允许过关。

## 最小视觉要求

- 玩家：简单 `ColorRect`、`Sprite2D` 或基础形状。
- 墙体和障碍：不同颜色的 `ColorRect` 或 `Polygon2D`。
- 钥匙：黄色小方块或简单图标。
- 出口：绿色方块或简单门形，未激活和激活状态应有明显区分。
- UI：使用 `CanvasLayer` 显示当前提示文字。

## 输入映射

在 `project.godot` 中配置以下输入动作：

- `move_left`：`A`
- `move_right`：`D`
- `jump`：`W`
- `space_rotate`：`Space`

不要把 `Space` 绑定到 `ui_accept` 后间接处理，应使用独立的动作名，避免和系统 UI 输入冲突。

## 脚本要求

### player.gd

需要实现：

- 读取当前重力向量。
- 根据当前重力计算移动方向、跳跃方向和下落。
- 使用 `move_and_slide()` 处理碰撞。
- 保持玩家在地面、墙面、天花板等不同表面上都能正常站立或滑动。
- 提供简单的撞墙/接触障碍状态，供教学提示触发。

### gravity_manager.gd

需要实现：

- 保存当前重力索引和重力向量。
- 提供 `rotate_gravity_clockwise()` 方法。
- 旋转主相机和 UI 根节点。
- 只在能力解锁后允许旋转。

### main.gd

需要实现：

- 控制教学提示的出现与消失。
- 监听钥匙拾取。
- 激活出口。
- 监听出口接触并触发过关。

## 验收标准

Demo 完成后必须通过以下手动测试：

1. 运行项目后玩家出现在左下角，不会穿出四边边界。
2. `A` / `D` 可以左右移动。
3. 初始阶段按 `Space` 无效。
4. 碰到右侧墙壁或障碍后，`W` 可跳跃，同时 `Space` 解锁。
5. 每点一次 `Space`，画面和 UI 都顺时针旋转 90 度，玩家落到新方向的地面上。
6. 连续旋转 4 次后，画面和重力回到初始状态，流程仍可继续。
7. 玩家不能通过普通跳跃直接拿到钥匙或通过出口。
8. 拾取钥匙后，出口变为激活状态。
9. 接触激活出口后出现通关提示。
10. 在旋转到四个重力方向中的任意一个时，玩家都不会掉出房间外。

## 完成要求

请提交一个可以直接用 Godot 4 打开运行的最小项目。代码中不要加入超出教学关需求的复杂系统。所有场景节点、脚本和输入映射应能在 Godot 编辑器中直接检查。最后提供简短说明，列出项目入口场景、已实现机制和手动验证结果。
