# 第二关推箱子可推动性与速度修复提示词

你是一个 Godot 4.7 游戏开发 Agent。请在 `projects/godot-gravity-tutorial-demo/` 项目中修复第二关推箱子的问题。

当前问题是：箱子仍然存在推挤问题，而且现在变成了根本推不动，或者推动速度非常慢。我不要它变快，我只要它能被玩家自然推动，并且推动时的速度不要慢。

## 修改范围

只修改 `projects/godot-gravity-tutorial-demo/`。

重点检查：

```text
scripts/player.gd
scripts/push_box.gd
scenes/level_2.tscn
```

不要修改 `projects/godot-gravity-tutorial-demo-(4.3)/`。不要重做整个关卡，不要加入菜单、存档、音效或新美术资源。

## 当前问题定位

当前 `PushBox` 已经是 `RigidBody2D`，但推动方式仍然是“玩家检测接触后，每帧对箱子施加一个力”。这种做法在 Godot 里很容易被下面这些参数一起拖慢：

- `mass = 2.0` 偏重。
- `linear_damp = 8.0` 阻尼偏大。
- `PhysicsMaterial.friction = 1.0` 摩擦偏高。
- 自定义重力使用的加速度可能偏高。
- `apply_central_force()` 受质量、阻尼和摩擦影响，推动速度不稳定。
- 玩家接触检测可能只在碰撞法线非常贴合时才触发，容易漏掉接触帧。

所以现在的表现是：箱子要么不动，要么像被粘在地上一样慢慢挪。

## 目标行为

修复后的推箱子应该满足：

1. 玩家贴身推动箱子时，箱子能被推动。
2. 箱子的移动速度应该和玩家推动速度基本一致，不要明显更慢。
3. 不需要让箱子变得很快，也不需要提高玩家移动速度。
4. 玩家松开方向键后，箱子立刻停止。
5. 玩家离开箱子后，箱子不再自己滑行。
6. 箱子不能闪现、吸附、穿墙。
7. 重力旋转后，箱子仍然可以被正常推动。

## 推荐修复方向

请继续使用 `RigidBody2D` 箱子，但把推动方式从“施加力”改成“接触时直接控制速度”。

### 1. 物理参数

先把物理参数调到可推动的状态：

```gdscript
mass = 1.0
linear_damp = 1.0
```

物理材质建议：

```gdscript
friction = 0.2 到 0.5
bounce = 0.0
```

不要用很高的 `linear_damp` 或 `friction` 把箱子粘在地上。

如果箱子的重力使用 `gravity_scale = 0`，就用 `constant_force` 或等效方式自定义重力；如果使用 `gravity_scale = 1`，就直接设置 `gravity_direction`。不要同时叠加两套重力。

### 2. 玩家侧

玩家在 `move_and_slide()` 后仍然检查是否接触箱子。

接触判断可以稍微放宽，不要因为碰撞法线一点点变化就漏掉推动：

```gdscript
if collision.get_normal().dot(push_direction) > 0.25:
    continue
```

这里的阈值只是示例，你可以根据实际测试调整，但不要让箱子只有在完美贴合时才能被推动。

玩家把推动信息传给箱子时，应该包含：

1. 当前推动方向。
2. 玩家当前输入方向对应的移动速度。
3. 本帧是否真的接触。

不要再把推动速度间接转换成一个很大的力。

### 3. 箱子侧

箱子收到玩家推动信息后，应该直接设置目标速度，而不是每帧累积力：

```gdscript
func apply_player_push(push_direction: Vector2, push_speed: float) -> void:
    if push_direction.is_zero_approx() or push_speed <= 0.0:
        return

    linear_velocity = push_direction.normalized() * push_speed
```

如果箱子在空中，需要保留自然下落，可以按当前重力方向合并速度：

```gdscript
linear_velocity = push_direction.normalized() * push_speed
```

如果这会让箱子在空中异常漂浮，再考虑保留一部分竖向速度，但不要为了推动而取消重力。

重要：

1. 玩家没有接触箱子时，不要继续设置箱子的推动速度。
2. 玩家松开方向键后，箱子的推动速度应为零。
3. 箱子不应该跨帧保存 `_push_velocity`。
4. 不要用 `move_and_collide()` 移动 `RigidBody2D`。
5. 不要用 `position += ...`、`global_position = ...` 或 `Tween` 移动箱子。
6. 不要用 `apply_central_force()` 来追求推动速度。

## 速度校准

请以玩家移动速度为基准：

```text
玩家 move_speed = 240.0
箱子推动目标速度 ≈ 240.0
```

如果测试中发现箱子比玩家慢很多，优先调整箱子自身的推动方式，而不是提高玩家速度。

如果测试中发现箱子比玩家快，可以降低目标速度，但不要低于 `200.0`。

推动期间，箱子的水平或竖向推动分量应该接近玩家移动速度，不能出现明显的“走一步停一下”。

## 碰撞与层级

请确认：

1. 玩家能和箱子发生碰撞。
2. 玩家被箱子阻挡，不能穿过箱子。
3. 箱子被墙和合法障碍物阻挡。
4. 箱子不能被开关提前吸附或瞬移。
5. 箱子接触开关后仍然能正常激活出口。

## 重力旋转

修复后仍然要保证：

1. 重力旋转结束后，箱子的重力方向更新。
2. 玩家推动箱子的方向基于当前屏幕方向。
3. 四个重力方向下，玩家都能推动箱子。
4. 箱子不会因为重力旋转而突然跳位或穿墙。

## 验收标准

请手动测试：

1. 玩家贴身推箱子，箱子能被推动。
2. 推动时箱子速度不慢，和玩家速度接近。
3. 松开方向键后，箱子立刻停止。
4. 玩家离开箱子后，箱子不再自己移动。
5. 箱子撞墙后停止，不穿墙。
6. 箱子接触开关后激活出口。
7. 在四个重力方向下，箱子都能被推动。
8. 玩家不能穿过箱子。
9. 第二关没有文字引导。

3. 现在的推动信息是如何传递的。
